# Деплой iptvs (Windows)

Деплой выполняет только субагент `iptvs-deploy`; main-сессия не копирует файлы
сама. Работаем только с Windows-сборкой.

## Источник и цели

- Источник: `build\windows\x64\runner\Release\`.
- Цели (обе обязательны):
  - `C:\Program Files\IPTVS`
  - `\\samsung-pc\c$\Program Files\IPTVS`
- Спрашивай подтверждение перед деплоем, если его ещё нет. Не деплой молча.

## Порядок

1. Убедись, что сборка свежая: `data\app.so` соответствует content-keyed AOT
   (см. `CLAUDE.md` → «Verification gate»). Если нет — остановись и попроси собрать.
2. Сравни файлы источника с **каждой** целью по SHA-256. Копируй только
   отличающиеся/отсутствующие файлы. Если всё совпадает — ничего не копируй.
3. Проверь `Get-Process iptvs` на каждой цели и **спроси пользователя, закрывать
   ли запущенные приложения**:
   - **Закрывать**: сначала попроси приложение закрыться
     (`Get-Process iptvs | ForEach-Object { $_.CloseMainWindow() }`), подожди
     3–5 секунд; если процесс остался — заверши `Stop-Process -Id <pid> -Force`.
     Дождись завершения и скопируй новые бинари прямо на место деплоя. На
     `samsung-pc` — тот же порядок через `PsExec64.exe` (мягкое закрытие, пауза,
     затем `taskkill`), учётка из `_netrc` (machine `samsung-pc`); секреты не
     выводить.
   - **Не закрывать**: не убивай процесс; переименуй занятые файлы (как минимум
     `iptvs.exe`, при необходимости DLL) в `<name>.old.<timestamp>` и скопируй
     новые. После деплоя напомни перезапустить приложение.
4. Удали старые backup-файлы (`*.bak`, `*.old*`, `*.orig`, `*.backup`, `*.1`,
   `*.2`) в целевых каталогах; заблокированные оставь до перезапуска. Не трогай
   `hwdec_override.txt` и другие посторонние файлы.
5. Скопируй отличающиеся файлы, исключая `.pdb`/`.lib`/`.exp`/`.ilk`/`.obj`.
6. Проверь SHA-256 изменённых файлов в обеих целях и отчитайся: скопировано,
   уже совпадало, переименовано, удалено, заблокировано.
7. Если доступ к `C:\Program Files` запрещён — сообщи, что нужны права
   администратора; не запускай elevated-процессы без явного согласия.

## Права на завершение процессов

Учётной записи `NT AUTHORITY\LOCAL SERVICE` выдано право **«Отладка программ»**
(SeDebugPrivilege): без него `Stop-Process -Force` над процессами другого
пользователя может падать с Access denied, с ним жёсткое закрытие работает
(проверено 13.11.2026).

1. `Win+R` → `secpol.msc` → Enter.
2. Локальные политики → Назначение прав пользователя.
3. Политика «Отладка программ» → двойной щелчок.
4. «Добавить пользователя или группу» → `LOCAL SERVICE` (или
   `NT AUTHORITY\LOCAL SERVICE`) → «Проверить имена» → ОК.
5. ОК, закрыть редактор.
6. Изменения действуют после перезапуска службы под `LOCAL SERVICE` (или
   перезагрузки компьютера).

## Опционально

MSI-пакет — только по просьбе:
`tool\package_windows_msi.ps1 -BuildDirectory build\windows\x64\runner\Release -Version <версия> -OutputPath build\msi\iptvs-<версия>.msi`
(см. `docs/updates.md`, раздел «Manifest and package signing»).

## Отчёт

Какой режим выбран (закрывать/не закрывать), какие процессы остановлены, что
пропущено/скопировано/переименовано/проверено, какие backup-файлы удалены,
итоговые хэши и нужно ли перезапустить приложение.
